# FusionPanel product delivery plan

**6 November 2026 · Baseline `master` at `0afd416` · Europe/Berlin**

Deliver one complete user journey per short cycle. The first user should be able to sign in to FusionPanel, create a MariaDB database, find it after reloading the page, and use a scoped SQL account to write and read data. Start with one preconfigured MariaDB service in a disposable environment. The first deliverable is a pilot a second person can run from a clean checkout using the documented steps.

The [delivery plan](DELIVERY_PLAN.md) and [W04 work map](waves/W04_2026-11-03/README.md) still define package ownership and dependencies. This plan sets the order for completing user journeys. Keep all capability and mode requirements in the [capability ledger](CAPABILITY_LEDGER.md).

## Cycle 1 — Create and use a MariaDB database

**User demo.** Sign in as an authorized operator, create a named database from the Databases screen, reload the page, and retrieve its connection details. Use a database-scoped account from a real SQL client to insert and read a unique value. Sign in as a second tenant and verify that the database is absent from its list and that direct access is denied. Restart the API against the same stores and show that the database and its ownership are still visible to the first operator.

**Acceptance scope.** Record this as the MariaDB case for `DB-03` and as supporting evidence for `SEC-04`, `SEC-12`, and the minimum SQL access needed for the demo. Record coverage for the exercised configuration. `DB-01`, `DB-04`, additional engines, and other host or container modes have their own acceptance criteria. Backup, restore, delete, and other unsupported actions must have an explicit availability state in the pilot.

### Backend contract to settle before UI work

- Agree one callable route and response shape for login, create, list, and read. Preserve existing public contracts or document a compatibility path. Derive the tenant from the persisted authenticated principal and apply authorization on every read and write. Align the browser cookie with the middleware and prove logout or revocation on a subsequent request.
- List and read from observed, tenant-owned state. A missing database stays missing. Validate the requested name and supported options, and demonstrate that the response reflects the engine. Use the existing ownership and job stores where their contracts fit. Reserve or otherwise reconcile creates so a retry cannot adopt someone else's pre-existing database or create a second resource.
- Use explicit fixture connection settings and generated credentials. Seed two persisted tenant memberships with the permissions needed for the demo. Start with the pinned MariaDB service and reuse `tests/fixtures/compose.py` where practical. Check whether the adapter needs a host client or a container execution strategy. Give the browser and API the same contract, and give the SQL client only the access needed for the created database.

## Definition of done

- A second person follows the runbook from a clean checkout or pilot artifact and achieves the documented result via the real product surface.
- The exact candidate passes applicable component, real integration, and E2E cases, including the named authorization, restart, failure, and recovery checks. Required lanes report `PASS`, `FAIL`, `BLOCKED`, or `NOT_RUN` separately. Follow the [test strategy](../testing/TEST_STRATEGY.md) for commands, fixture versions, sanitized output, and cleanup.
- The PR is reviewed and merged to `master`. Record the merge SHA, capability/mode evidence, and remaining limitations in the tracker. Rerun affected acceptance cases if the merged tree differs from the verified candidate. Close an issue only when its own scope is evidenced. [#29](https://github.com/scherenhaenden/FusionPanel/issues/29) was already closed at this baseline, and its status does not satisfy the pilot's runtime gates.
- Label the deliverable with its verified scope. The existing [W04 release decision](waves/W04_2026-11-03/final/RELEASE_DECISION.md) governs the full release. Clean install, update, independent recovery, and required full OS/provider qualification remain release gates.
