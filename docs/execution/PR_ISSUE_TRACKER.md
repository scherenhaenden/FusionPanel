## Association rules

- Keep package implementation PRs linked to their primary issue and recorded in this table. Record directly related docs/maintenance PRs with their relevant issue; state why no issue applies when none is relevant.
- Use `Refs #N` while review, acceptance or evidence remains incomplete. Use `Fixes #N` only after all acceptance criteria and final test evidence have been recorded before merge, because GitHub may close the issue automatically.
- After a merge, record the exact merge commit, user-visible change, executed unit/integration/E2E commands and results, and remaining limitations. For `Refs` PRs, close manually only after that evidence is present.
- Use regular merge commits for all new integrations. The four squash merges above are historical and are documented here for accurate provenance; do not rewrite their history.
- Update this table whenever a package PR is opened, retargeted, merged, or abandoned. The 162-row [capability ledger](CAPABILITY_LEDGER.md) remains the acceptance source for product capability status.
