The capability ledger defines **component owner → integration owner → E2E owner → closure owner** for every feature. Capability readiness is scored across those four delivery stages at 25 points each. A documented component slice is credited at 25 only where the package explicitly implements that slice; an explicitly partial slice receives 12.5. Integration, real E2E, and closure receive no credit until evidence passes. No feature has completed all downstream gates, so none is 100% ready.

Work-package readiness is scored as **scope / implementation artifact / unit evidence / real integration / E2E acceptance**, 20 points per gate. An open, partial implementation PR receives 10 points for the implementation gate. A gate marked BLOCKED, ignored, or not run earns no credit; a partial integration gate earns 10. Package percentages are shown as whole numbers.

The weighted feature score is 400 of 16200 possible readiness points (2.47%). This does **not** mean 2.47% of features work: **0 of 162 capabilities are fully accepted**. Current technical evidence covers component slices for 22 features only.
