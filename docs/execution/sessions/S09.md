Domain/path validation, deterministic rendering and compensations. Include meaningful negative cases and state invariants, not only construction/serialization tests.

## Integration verification

## End-to-end verification

Create domain, serve uploaded content and undo failed provision after S26. If runtime prerequisites are not available yet, provide executable case definitions and record BLOCKED with the exact dependency. A blocked/unrun case is not a pass. Final acceptance requires actual observed user outcome.

## Delivery and exit gate

Commit and push a focused branch; create a PR against **master**, do not merge it, and report its URL. Link the task issue and capability IDs. Include changed behavior, unit/integration/E2E commands and observed results, blockers, fixture teardown and known limitations. Reviewable code without required real evidence remains implementation-complete at most, not capability-accepted. Do not change repository visibility/settings or unrelated dependencies.
