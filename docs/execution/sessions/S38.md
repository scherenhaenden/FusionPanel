## Required behavior and design

## Unit verification

Config validation and update decision rules. Include meaningful negative cases and state invariants, not only construction/serialization tests.

## Integration verification

Disposable Debian VM install/update/reboot. Use actual dependencies in disposable fixtures. Test doubles may verify boundary failures, but cannot qualify real dependency behavior. Capture exact commands, dependency versions and sanitized evidence.

## End-to-end verification

Failed update returns working services; local recovery works without UI. If runtime prerequisites are not available yet, provide executable case definitions and record BLOCKED with the exact dependency. A blocked/unrun case is not a pass. Final acceptance requires actual observed user outcome.

## Delivery and exit gate

Commit and push a focused branch; create a PR against **master**, do not merge it, and report its URL. Link the task issue and capability IDs. Include changed behavior, unit/integration/E2E commands and observed results, blockers, fixture teardown and known limitations. Reviewable code without required real evidence remains implementation-complete at most, not capability-accepted. Do not change repository visibility/settings or unrelated dependencies.
