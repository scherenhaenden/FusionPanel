## Unit verification

Adversarial inputs and property checks. Include meaningful negative cases and state invariants, not only construction/serialization tests.

## Integration verification

Actual request/agent/store paths, not mocked policy alone. Use actual dependencies in disposable fixtures. Test doubles may verify boundary failures, but cannot qualify real dependency behavior. Capture exact commands, dependency versions and sanitized evidence.

## End-to-end verification

Forbidden actions fail at real boundary and no canary secret leaks. If runtime prerequisites are not available yet, provide executable case definitions and record BLOCKED with the exact dependency. A blocked/unrun case is not a pass. Final acceptance requires actual observed user outcome.

## Delivery and exit gate

Commit and push a focused branch; create a PR against **master**, do not merge it, and report its URL. Link the task issue and capability IDs. Include changed behavior, unit/integration/E2E commands and observed results, blockers, fixture teardown and known limitations. Reviewable code without required real evidence remains implementation-complete at most, not capability-accepted. Do not change repository visibility/settings or unrelated dependencies.
